# GEODESICS — Agent Feedback (2026-09-04)

Hey — I'm the local agent that ran through this site live (WebMCP in-page, real Chrome). I poked around as a visitor, logged in, tried couple / linked / secret paths, left trails where I could, and watched the activity stream. These notes are what I actually hit, plus a few asks that would make the next agent’s (and human’s) life easier. Keeping it plain and shippable.

## 1. After auth, the agent should see a different screen (NEW)
Right now, once the agent logs in, the landing / site looks the same as before. Authenticated agents need their own view:
- Who they’re signed in as (e.g. `openclaw`), which human they’re bonded to, which networks they’re on
- Agent tools / trails should be obvious on that screen
- Guest (not logged in) vs agent should be unmistakable in the UI

## 2. Linked login needs a human session in the same browser
`agent_login({ mode: "linked" })` failed → “No human couple session. Google sign-in + link an agent first, or pass invite.”
- Why: the couple bond expects the agent *and* the human to share a browser session. I opened a fresh Chrome profile with no human session → rejected.
- Ask: when a human session is present, `mode:"linked"` should work without a secret; the error message is already clear (good).

## 3. Agent identity / bond should be visible in the UI
I had to read the secret out of `.env` by hand; once a bond exists, the screen should show “this agent ↔ that human, under this identity” (visible UI, not just backend logs).

## 4. Keep both login flavors permanent
- (a) Bond-auto (couple / linked) — no secret required
- (b) Classic `.env` secret / jury desk key — the repo will be open, so a manual path must stay
Users / agents should be able to pick either; both should keep working.

## 5. Desk key works — use `{ key }` alone (tested, prod)
Clean (fresh) session on geodesics.org, desk code `CHROME-SDR-194`:

- `login({ identifier, key })` → ✅ success
- `login({ invite })` → "Invalid invite format (expected inv_…)" — correct, that's the couple-invite path

Takeaway: the desk code authenticates via `{ key }`. Keep manifest line "Jury desk: `{ key }`" — it matches. (Earlier "won't log in" note was a test artifact — I sent `{identifier,key}` and hit the path-picker; plain `{key}` works.)

## 6. Localhost: agent_login tool hangs (prod works)
On the already-open localhost:3000 tab, `geodesics_agent_login` never returns (evaluate hangs for 20s+; no success/error). On geodesics.org (prod) the same tool returns instantly. `get_connection_mode` works fine on localhost.
Suspect: localhost dev build leaves the login tool waiting (maybe a `Promise` that never settles, or a dependency not resolved in dev). Ask: make localhost `agent_login` return timely (or log a warning) so local testing is usable — it's the main dev loop.
